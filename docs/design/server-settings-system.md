## Contracts and boundaries

- Administrators see multi-user administration destinations only when multi-user mode is enabled. The server independently checks current user identity and role; hiding controls is not authorization.
- Server configuration setters persist a cloned configuration before publishing live values. Unrelated configuration, including ownership and sharing, remains intact.
- Settings state belongs to `store.js`; WebSocket access uses `ws-ref.js`; extracted modules use direct imports. No prototype controllers were copied.
- Related fields use explicit draft/save. Page navigation retains drafts. Closing with drafts requires a custom choice; reopening within the tab retains them. Reload is explicitly described as discarding unsaved drafts.
- SMTP and environment values stay masked. There is no invented Server → Personal → Project → Mate hierarchy. Only actual project-over-shared environment precedence is shown.
- Device subscription endpoint/VAPID metadata remains browser-local; it is not an account preference. No new browser-local preference writes were introduced.
- Personal Email remains a mailbox surface; server Email delivery is outgoing administration SMTP. Unrelated workbenches remain outside Settings.
- Compact shell: 196px desktop navigation, 32px destination rows, 700px normal content width, 20px page titles, 14px section titles, 13px labels, 32px actions, 36px fields. Flat rows, full-row selection, separate focus indicators, keyboard selectors, focus return, and reduced-motion overrides.

Use `settings-ui.css` for shared interiors; keep shell placement and page-specific layouts in their own stylesheet. Server, Personal and Project settings now share 20px page titles, sentence-case 14px section headings, 13px field labels, 36px fields, 32px actions and 8px control corners. Group related fields with a quiet `.settings-card` section (flat, without a surrounding box), `.settings-field` for stacked inputs, or `.settings-field-row` / `.settings-toggle-row` for aligned compact rows. Do not add another set of per-page control dimensions. Use `.settings-hint` for scope/effect copy and `.settings-form-actions` / `.settings-status` for save feedback; retain the controller's actual persistence contract.

For selectors, keep a labelled native `select` as the value and event source, then call `enhanceSettingsSelects(root)`. Call it again for newly inserted controls; existing controls are left intact. User choices dispatch the original native `change` event once; enhancement never saves on its own. ## Per-user disk usage

Storage now includes an administrator-only usage table with user, Linux account, allocated space and file count, plus total measured and system/unattributed usage. At the user's request, scope includes mapped Linux home directories and registered project files alongside Clay data. File UID determines attribution; project sharing or project ownership is not treated as proof of file ownership. Missing/ambiguous Linux mappings display Unavailable. Outside Linux OS-user multi-user mode, usage is grouped by registered project owner instead of Linux UID. Nested projects use their own owner; ambiguous shared paths/hard links and non-project Clay data are unattributed. A single-user installation assigns unowned projects to its local account. Home directories are not automatically scanned in project-owner mode, but a home explicitly registered as a project remains in scope.

Metadata scans count overlapping paths and hard links once and skip symlinks and nested mounts. Project roots are scanned first, then mapped homes and shared Clay data. Large scans continue in the background with polled progress instead of stopping at a fixed entry/time cap; unfinished totals are explicitly lower bounds. Unreadable paths, unresolved mapped identities and limits produce a partial result; totals are then labelled as lower bounds. Concurrent scans are coalesced and results cached for 30 seconds. Refresh failures retain the preceding measurement; authorization failures hide it. This is a scoped disk-usage report, not a whole-disk quota or a delete action. Image retention continues to affect only expired chat images.

## State first, editing by choice

The settings design principle is to show saved state first and enter an editor through an explicit Edit action. Do not make a permanent form the resting page. Apply this to coherent configuration groups; operational commands remain deliberate actions. Summaries keep secrets masked and distinguish saved configuration from verified delivery or runtime effectiveness.

Email delivery implements this pattern: configured and unconfigured summaries, Edit with focus entering the form, Save returning to the summary, and Cancel with a custom dirty-draft confirmation. Failures retain the editor and values. Edit also retains access to test delivery and confirmed removal. The existing server permissions and masked-password sentinel are unchanged. This establishes the pattern; other existing settings groups have not all been converted in this change.

Dangerous operations follow the same intentional-entry principle. Operations shows a Danger zone warning and Review shutdown entry before exposing the shutdown form. The review explains service loss and host-level recovery, retains the typed confirmation and final custom confirmation, and provides Back with focus return and cleared confirmation text. Disclosure itself sends no lifecycle request.


Invitations is a section within Users, below Accounts with a divider. Desktop and narrow navigation share one Users destination; previously selected admin-invites routes resolve to Users. Both lists load independently, retaining account actions, invitation generation/copy/email/revocation and existing server authorization.
