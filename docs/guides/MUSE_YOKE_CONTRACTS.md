# Muse YOKE contract coverage

Muse is registered independently through YOKE on `feat/muse-yoke-contracts`, based on `3a583ff8`. The dependency is pinned to the published `@muse-code/sdk@1.4.7`. The existing Muse implementation was inventoried and selectively ported from the read-only integration worktree. The common host refactor was retained; no Muse execution branch was added to `sdk-bridge.js`.

Scope: provider-specific execution, discovery, options and protocol normalization belong inside YOKE. Clay retains product policy, authentication/review authority, persistence and rendering. This implementation uses existing common services; the optional image-event documentation adds no mandatory interface, dedicated generation method or general conformance redesign. SDK operations without a supported product contract remain documented limits.

## Published SDK evidence

The evidence below refers to files inside the installed, lockfile-pinned `@muse-code/sdk` package, not unpublished CLI internals. `dist/src/msp.d.ts` contains the generated stable protocol declarations; its `MspMethod` union at line 3393 enumerates the enrolled methods. `dist/src/index.d.ts`, `connection/connection.d.ts`, `connection/spawn.d.ts` and `facade/session.d.ts` expose the public Connection, spawn handshake and Session composition used here. The high-level MuseClient omits session `config`; its `facade/client.d.ts` explicitly excludes that field pending its capability checks. Clay therefore uses the public low-level connection, checks the `sessionMcp` grant and constructs an actual SDK Session.

## Scoped shared and native skills

Shared skill delivery is instruction-based, not native registration. `yoke/muse-skills.js` reuses the existing YOKE discovery/index/reference helpers; it builds the shared index for the first authorized turn on both fresh and resumed queries, refreshes changed indexes/catalogs on later turns, and reads explicitly referenced content on every turn with the existing 32768-character bound/truncation marker. A shared `/skill arguments` is translated to `$skill arguments` only when no native selector has the same name. A collision uses native `/name` versus shared `$name`; this rule is included in the model guidance. Unknown dollar tokens remain ordinary prompt text without invented instructions. Missing slash/native selections reject before native turn admission, as does a referenced discovered skill whose instructions become unreadable.

`session-skill-scope.js` binds the existing `skillOptions` root/disable options to the exact live session and query through a server-owned availability callback. It reuses personal-connection owner/foreign/delegation checks rather than trusting model flags. Muse requires that callback before discovery, native listing or referenced reads; `skipSkills`, disabled options, title/read-only scopes, missing scope, foreign/shared/delegated sources and mapped OS identities do not gain personal skills. The callback revalidates query generation, session existence, original owner and live access. Reads check scope before and after file access and again immediately before turn submission. Revocation after prior delivery retires subsequent delivery; it cannot erase context already delivered to the provider.

Discovery uses read-only scoped filesystem operations, with no migration/installation/import/activation writes. Optional Clay-specific skills are delivered from owner/project `.clay/skills`, plus the existing bundled Clay skills; Clay names found only in generic vendor roots are not delivered or copied. Native `clay-*` selectors (including qualified names) are excluded, so the reserved namespace cannot silently switch to a vendor-global install. No generated files or skill bridges are placed in vendor-global discovery roots.

Native catalogs are fetched from the actual loaded SDK session with `skill/list` and retained per query, never on the shared adapter. An authorized slash selection or `invokeSkill` is validated against the current native catalog and sent as a typed skill part with the exact selector/arguments. Shared instructions are separate text parts, never fake native registrations. The session-only `commands_changed` event supplies native names and a replacement shared-name snapshot to the existing common slash flow; the common processor preserves persistence/rendering ownership. No UI layout change or new canonical action is introduced. Native availability is learned only after a scoped runtime session opens, not by unscoped adapter initialization.
